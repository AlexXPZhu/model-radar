# ModelRadar · 模型雷达

**让模型的行为，留下证据。**

一款在本机运行的 OpenAI-compatible API 检测工具。通过中文界面采集响应、参数兼容性、重复稳定性和用量差异，解析响应里已有的侧信道信号，并保留可复核的原始证据。

> ModelRadar 做的是行为指纹与侧信道分析，无法保证识别底层模型。它不提供模型身份概率，也不把服务端自报的 model 当作身份凭证。

## 开始使用

需要 Python **3.10+**，无需安装任何第三方依赖。

```console
python app.py
```

Windows 可双击 `start.bat`，或运行 `py -3 app.py`。macOS / Linux 通常使用 `python3 app.py`。本地服务仅监听 `127.0.0.1`，自动选择可用端口，并在默认浏览器打开界面。保持启动窗口运行，按 Ctrl+C 退出。可用 `--port 8765 --no-browser` 固定端口或不自动打开浏览器。

填写 Base URL、模型 ID 和 API Key，选择方案后点击“开始检测”。Base URL 应包括 API 前缀，例如 `https://your-provider.example/v1`；脚本只追加 `/chat/completions`。密钥只填本身，无需添加 `Bearer`。默认快速观察为 **6 项 × 3 次 = 18 次请求**；完整方案为 **29 项 × 3 次 = 87 次请求**。真实请求会产生服务商费用。

也可以先点“获取列表”向端点索取它自报的模型 ID，再从中挑选。“分词与计量”方案只跑基线加 7 个分词探针，共 8 项，用于建立或比对分词参照。

## 功能

- 中文响应式界面：连接配置、测试项选择、请求数量预览和实时进度。
- 快速观察、参数探测、完整指纹三种方案，支持自定义测试项、重复次数、超时、间隔与长文本长度。
- 保存原始 JSON / SSE、HTTP headers、model、response ID、system_fingerprint、完整 usage 和结束原因。
- 客户端 TTFT、总延迟、精确输出检查、重复文本统计。
- 自动标记同一请求体的输入计数变化、stop 未截断、概率数据缺失。标记是观察，不是换模判决。
- 侧信道信号面板：响应 ID 前缀、system_fingerprint、请求与返回模型名是否一致、响应头字段、logprobs 的 token 切分、流式块间节奏、usage 里的缓存/推理字段。全部来自已保存的响应，不额外发起请求。
- 分词参照比对：把可信官方端点的一次检测设为参照，之后每条记录都会和参照库做差分比对，并检查请求的模型是否与它自己的参照一致。
- 模型列表发现：探测 `/models`、前缀根路径、`/api/tags` 等路由，保存每次尝试的原始响应供核对，并提示请求的模型 ID 是否出现在自报列表中。
- 历史记录、逐次证据查看、报告预览和 JSONL / CSV / Markdown / 原始正文 ZIP 导出。
- 导入旧版 `results.jsonl`，按 2.0 精确字符规则重新检查固定答案。导入的文件路径不会被执行或读取。
- 两批结果对照，显示语料哈希是否一致。可以比较中转站与官方端点，或不同时段的检测。
- 内置虚构演示结果，不需要密钥，不发起 API 请求。
- 原命令行工具保留：`python collector.py --help`。

## 数据与密钥

检测数据默认写入项目的 `data/<run_id>/`，模型列表探测写入 `data/_discoveries/<endpoint>/`（以 `_` 开头的目录不会被当作检测记录），也可通过 `python app.py --data-dir <directory>` 指定目录。开始检测时选中的模型列表会复制为记录里的 `models.json`。历史文件和密钥不应提交到 Git；项目已忽略 `data/`、`.env` 和本地缓存。

UI 密钥仅在页面输入框和当前运行的内存中使用，提交成功后清空输入框。不存 localStorage，不读取已有 OPENAI_API_KEY，不写配置或报告。退出后不会记住密钥。UI 没有在线账户、遥测、CDN 或第三方脚本；请求仅发送到你填写的 API 地址。Python 遵循系统代理配置，因此代理仍可能参与网络通信。

响应体保存为客户端读取的原始字节，精确匹配当前 API key 的片段会脱敏。响应头按名单脱敏：cookie、authorization、各类 api key 与 session/token/credential 命名的头部会被替换，其余字段（如 `x-tokenizer-version`、`x-ratelimit-*`、`retry-after`、`x-request-id`）按原样保留，因为它们正是要观察的侧信道。未知或编码后的秘密可能无法识别，导出分享前请检查。导入旧 JSONL 时只保留证据字段并丢弃 headers、request 和 raw_file；未知藏在正文里的秘密仍需要人工检查。

本地控制接口检查 Host、Origin 和每次启动的会话 token，不提供跨域访问。只用于个人本机使用，不应通过反向代理暴露到公网。TLS 校验启用，不跟随上游重定向；非本机 API 必须 HTTPS。

## 如何理解结果

- HTTP 200 表示服务端接受了请求，不等于所有参数生效。logprobs 缺失、stop 未兑现需单独核对。
- 固定答案从 2.0 起精确比较，前后空格也计为未通过；UI 同时保留去除首尾空白后的文本差异计数。JSON 项目检查简单的 `{"x":7}` 对象，不能证明服务端实施了硬 schema 约束。
- TTFT 从请求开始到首个非空 `delta.content`，包含网络、排队与缓冲；role、推理和工具字段不计入。非 SSE 响应没有流式 TTFT。
- 模型列表是端点自报的元数据，和响应里的 model 字段同一性质：它列出的是可以宣称的东西，不构成模型身份凭证。一个用低价模型顶替的中转站照样会列出高价模型名。
- 响应 ID 前缀、`system_fingerprint`、响应头都由服务端生成，可被转发或改写；相同前缀只说明链路相似。流式节奏反映缓冲与排队，整段一起到达通常是缓冲而不是生成速度。
- logprobs 的 token 切分直接反映服务端分词器，是当前语料里最强的单点信号；但要判断“像哪个模型”仍需对照端点。分词探针只能发现“计量完全不读正文”这类情况，不能单独识别模型。
- 用量、缓存字段、response ID、模型名均可能由代理转换。

## 分词参照

每个分词探针都是同一句包装语加一段不同的正文，其中 `tokenizer_base` 正文为空。比对时用每个探针的输入计数减去 `tokenizer_base`，在固定开销与计量口径一致的假设下，可抵消固定上下文的计数影响。结果表示这些探针的计数差分是否一致；相同数量不证明 token 切分相同，也不证明模型身份。

**参照库默认是空的。** 本项目不内置任何未经实测的数字。建立参照的步骤：

1. 用“分词与计量”方案检测一个你信任的官方端点（例如服务商自己的 API，而不是中转站）。
2. 在该记录的详情里点“设为分词参照”，填写名称与系列。参照存入 `data/_references/tokenizers.json`；`reference/tokenizers.json` 是可随仓库分发的内置参照，同样的格式。
3. 之后检测中转站时，记录详情和报告会列出最接近的参照；如果请求的模型名在参照库里有对应参照，会直接说明两者是否一致。

解读时注意：

- **计量不稳定时不下结论。** 每个探针会各自取重复中的众数，所以混合路由的运行会拼出一个任何单一上游都没产生过的向量。出现这种情况时界面和报告都只提示不稳定并要求重测，不会显示“探针计数差分完全一致”。
- **报告里的分词比对按当前参照库实时重算**，详情、Markdown 预览和导出的 ZIP 用的是同一份结果；磁盘上的报告文件保留检测当时写下的内容。检测开始时保存 `references-collected.json`，包含实际参照、内容 SHA-256 和分析版本。导出另含 `references-analysis.json`（本次重算使用的参照）及 `report-collected.md`（原始报告）；`report.md` 是按当前库重算的结果。旧记录没有当时快照时，不能恢复当时参照内容。
- **分词器只能区分系列，不能区分大小。** gpt-4o 与 gpt-4o-mini 共用 o200k 分词器，同系列的降级替换不会在这里体现，需要结合能力与延迟线索。它擅长发现的是跨系列替换，例如声称是 Claude 实际是别家模型。
- “计数差分接近，非完全一致”可能是分词器版本更新，也可能是计量为估算值。
- 与声明模型的参照不一致时，还有一种可能：中转站没有透传上游 usage，而是自己用 tiktoken 之类估算。此时计数反映的是中转站的估算器，不是上游模型。请对照原始响应核实。
- “输入偏移”是探针计数差分完全一致时，空载探针比参照多计的 token 数。非零表示每次请求可能附带了隐藏上下文，或计费口径不同。
- 只有探针文本完全相同（按 `prompt_sha256`）的项才会参与比对；探针少于 4 项（含 `tokenizer_base`）时不做判断。2.0 的旧记录只有两个探针，不足以比对。相同请求的 token 差异可能来自隐藏上下文、统计口径、适配器或路由；单个线索无法确认模型身份。
- 代码生成与中文改写、英文写作需要人工检查。应用不执行模型生成的代码。
- `complete` 是协议完整性，不代表正确答案，length 结束或拒答仍需检查 finish_reasons。
- “完整指纹”项数随语料版本变化，界面显示的项数由后端提供，不以文档为准。
- UI 延迟中位数只计算完整响应；Markdown 明细的延迟中位数包括有延迟记录的失败调用，请注意口径。
- 401/403 自动停止。429、502、超时等会记录并继续，无自动重试或参数回退。
- 停止会中止当前网络读取并保存部分证据，之后不发起新请求。超时按整次请求计时，通过关闭连接中止持续输出或停滞的响应；系统域名解析在 socket 创建前可能延迟返回，解析完成后会再次检查截止时间。每次检测正文上限 8 MB，事件上限 10000；达到限制会记为不完整并保存中止原因。强制退出进程仍可能无法完整落盘。
- 提示词通常要求短回答，但没有给所有请求加统一输出上限，因为上限参数本身在被测。请求次数预览不等于费用上限。
- 相同语料哈希只是可比性的一个条件；还需要相同采样配置、时间、区域和负载。三次重复只能初筛，简单题不能区分高级模型。

## 命令行与开发

```console
python collector.py --list
python collector.py --dry-run
python collector.py --base-url https://your-provider.example/v1 --model YOUR_MODEL --prompt-key
python -m unittest discover -s tests -v
```

项目采用 Python 标准库 HTTP 服务与原生 HTML / CSS / JavaScript。无构建步骤，可离线打开 UI；实际检测需要访问所填 API。测试使用本地模拟服务，不消耗真实 API 费用。GitHub Actions 在 Windows、macOS、Linux 的 Python 3.10 / 3.13 上运行相同测试。

接口参考：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[SSE 事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。兼容服务不一定实现全部协议。

## 项目结构

```text
app.py              本地服务、任务运行、导入导出与观察汇总
collector.py        原始 API 采集、模型列表发现与 CLI
transport.py        请求截止时间、取消与响应大小限制
fingerprint.py      侧信道信号提取与分词参照比对（不联网，只读已采集记录）
reference/          可随仓库分发的分词参照（默认为空）
web/                中文 UI，不依赖在线资源
tests/              模拟 API 和本地安全边界测试
data/               个人检测数据（Git 忽略）
```
